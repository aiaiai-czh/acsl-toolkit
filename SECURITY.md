# Security policy

## Supported versions

Security fixes are provided for the latest published version of ACSL Toolkit.
Older preview builds may be asked to upgrade before a report is investigated.

## Reporting a vulnerability

Use the repository's [private vulnerability reporting
form](https://github.com/aiaiai-czh/acsl-toolkit/security/advisories/new) when it
is available. If private reporting has not yet been enabled, contact the
maintainer through the publisher profile before sharing technical details. Do
not open a public issue containing an exploit, credential, private source file,
or personal information.

Include the affected extension version, VS Code version and host, reproduction
conditions, potential impact, and the smallest safe proof of concept. Remove
local paths, usernames, tokens, and unrelated editor logs.

ACSL Toolkit does not intentionally perform network requests, collect telemetry,
start external processes, or write workspace files. Reports showing behavior
outside that boundary are treated as security-sensitive.
